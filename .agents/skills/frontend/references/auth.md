# Auth: sessions, gates, permissions

_Part of the `frontend` skill. **[enforced]** = checked by ESLint, `check:arch`, typecheck, hooks or CI._

Source of truth: grov-be `modules/auth` and `modules/access`, project docs 10 (auth architecture) and 11 (access model), D37.

## Web sessions

- One account per person; two audiences with separate sessions and cookies: `APP` (customer app) and `ADMIN` (admin console). `AppProviders audience={…}` picks it per app.
- grov-be sets httpOnly `<prefix>_at` / `<prefix>_rt` (admin `<prefix>_admin_at` / `_admin_rt`) and a readable `<prefix>_csrf`. `VITE_COOKIE_PREFIX` must equal grov-be's prefix.
- Tokens never touch JS **[enforced: `check:arch` storage-access; ESLint bans js-cookie, crypto-js]**. Never parse, store or log them; never send `Authorization` headers from the web apps.
- Access tokens last 15 minutes. The API client refreshes on any 401 outside `/v1/auth/*` and retries once; if the refresh fails, `onSessionEnded` clears server data and (for someone who was signed in) says so.
- "Am I signed in", gates and access come only from `useMe()` (`GET /v1/me`). After any call that changes the session, invalidate `queryKeys.me` (the auth hooks already do).

## Sign-in flows

| App      | Flow                                                                                                                | Pieces (`@grov/shared`)                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Customer | Email → 6-digit code → (new) name, last name, phone → in. Or Google. No passwords (grov-be refuses them for `APP`). | `EmailStep`, `CodeStep`, `ProfileStep`, `GoogleSignInButton`, `useSignInStore` |
| Admin    | Email + password, or Google, `audience: 'ADMIN'`; forgot/reset by email link                                        | `PasswordSignInForm`, `ForgotPasswordForm`, `ResetPasswordForm`                |

- Every sign-in sends `device: webDevice()` (stable per-browser UUID v7).
- Terms version comes from `GET /v1/config` (`legal.termsVersion`), never hard-coded.
- Lookup endpoints must not reveal whether an account exists; the email-code flow answers the same for both.

## Gates

`Me.gates`: `VERIFY_EMAIL`, `ADD_PHONE` (after Google sign-up), `ACCEPT_TERMS`, admin `MFA` / `MFA_ENROL`. `RequireAuth` sends anyone with a gate to the app's `finish-account` route, which renders `<AccountGates>`. New gate → handle it in `AccountGates` and add its code to `Gate`.

## Permissions (admin)

- Keys are `module.resource.action`, declared in grov-be (`definePermission`). The typed list is `PERMISSIONS` / `PermissionKey` in `@grov/models`, generated by `yarn generate:permissions`. Use the constants, never a string **[enforced: `check:arch` permission-literal]**.
- Source: `Me.access.admin.permissions` (admin-audience calls only). Helpers: `usePermissions()` → `can(key)`, `check({allOf, anyOf})`; `<Can permission>`; route `handle.requires` (`routing.md`); nav `requires`.
- The server is the authority. A hidden button is a courtesy; a `403 PERMISSION_DENIED` still needs `errorMessage`. `401 AUTHZ_CHANGED` (roles changed) is absorbed by refresh-and-retry, after which `/v1/me` has the new permissions.
- Admin data is scoped to the session's store. `StoreSwitcher` uses `/v1/admin/active-store`; switching invalidates every `['admin', …]` query.

## Never

Keep tokens or the registration ticket in storage; build a redirect from a query param without `safeRedirect()`; trust a client permission check for something the server does not also check; show different copy for "account exists" vs "doesn't".
